# 오늘의 모찌 — 00~04 구현 안내

## 2026-10-27 추가: 등급별 개봉 영상

현재 앱에는 하단 탭과 뽑기·도감·교환 화면도 있습니다. 아래 본문의 00~04 한정 범위 설명은 초기 구현 시점의 기록입니다.

- 일반·희귀는 기존 기본 영상(`opening-myth.mp4`)을 3초부터, 영웅은 같은 영상을 처음부터 재생합니다. 기본 파일 이름은 기존 참조 보존을 위해 유지했습니다.
- 전설은 `assets/gacha/opening-legend.mp4`(약 6.04초), 신화는 `assets/gacha/opening-mythic.mp4`(약 7.04초)를 사용합니다. 새 영상은 784×1176, 24fps이며 기본 영상과 같은 세로 2:3 구도입니다.
- 한 묶음의 뽑기 결과가 확정되면 최고 등급의 영상을 한 번만 로드·재생합니다. 영상별 결과 전환 시점과 진동 시점은 `src/constants/gacha.ts`의 `openingClips`에서 관리합니다.
- 2~10장 결과는 봉인된 카드로 시작하고 하나씩 또는 모두 열 수 있습니다. 영상 건너뛰기·재생 실패는 이미 받은 결과를 보여 주며 다시 추첨하지 않습니다. 동작 줄이기에서는 영상 로딩도 생략합니다.
- 결과를 가져오는 경계는 기존 `useGachaStore.pull` → `mockGachaService.pull`입니다. 현재는 로컬 시연 추첨과 보유량 계산을 사용합니다. API가 준비되면 이 경계에서 서버가 확정한 결과와 잔액을 반영하도록 변경하고, 영상 선택과 카드 공개는 그대로 사용할 수 있습니다.
- 실제 모바일 영상·진동·앱 복귀 검수는 별도 확인이 필요합니다. 자동 테스트는 등급별 영상 선택, 2~10장 최고 등급과 카드 공개, 진동·전환 시간, 재생 실패·건너뛰기·동작 줄이기를 확인합니다.

기준 Figma: [목업_모찌의 기록실](https://www.figma.com/design/eGypnYD3GT4txEj6GtbJ3b?node-id=217-3378).
Figma MCP로 아래 프레임의 디자인 컨텍스트와 스크린샷을 읽었습니다. Figma 파일은 수정하지 않았습니다.

## 실행

Node 24.18.0, npm 11.16.0 기준. 모든 명령은 `frontend`에서 실행합니다.
PowerShell 실행 정책 오류가 나면 `npm.cmd`, `npx.cmd`를 사용합니다.

```sh
npm ci
npm start
# 개발용 웹 미리보기
npx expo start --web --localhost --port 8081
```

SDK 58과 호환되는 Expo Go/개발 빌드에서 QR 코드로 확인합니다. 폰에서 연결하려면
`--localhost` 없이 `npm start`를 사용하고 같은 네트워크에 연결합니다.

## 구성

- `src/app`: Stack 라우트와 Provider. 화면 구현은 각 기능 폴더에 있습니다.
- `src/theme/tokens.ts`: Figma 색상, Noto Sans KR, 타이포그래피, 간격, 반경.
- `src/components/ui`: 버튼, 입력/메모 입력, 헤더/스크린, 칩, 체크박스, 카드/기록 행,
  그림 영역, 로딩/진행률, 오류 배너/빈 상태, 시트/확인 모달.
- `src/components/emotion`, `src/constants/emotions.ts`: 감정 이미지·선택·배지와 단일 정적 매핑.
- `src/features/auth`, `home`, `diary`, `calendar`, `search`, `settings`: 화면과 상호작용.
- `src/stores/useAppStore.ts`: 로그인 프로필, 작성 초안, 기록, 저장/그림 상태.
- `src/mocks`: 2026년 10월 Figma 예제 기록, 로컬 비동기 서비스, 일회성 오류 주입.
- `src/services/api.ts`: 기존 Axios 클라이언트 확장. 화면에서 실제 API를 호출하지 않습니다.
- `src/services/queryClient.ts`: 공용 QueryClient. 검색은 Mock 서비스를 호출하는 mutation입니다.
- 기존 `src/features/home/HomeScreen.tsx`, `src/shared/api/health.ts` 및 서버 연결 테스트는 보존했습니다.
  해당 서버 확인 화면은 제품 라우트에 연결하지 않았습니다.

## 이미지와 글꼴

사용자 PNG는 경로·이름·파일 내용을 유지합니다. 선택 화면, 캘린더, 기록 행, 그림 상태 등에서
모두 `EmotionImage`를 사용하고 `resizeMode="contain"`으로 원본 비율을 보존합니다.
원본은 1024×1024의 질감 있는 이미지이므로 Figma 선화와 시각적 차이가 있습니다.

| 감정 | 원본                 |
| ---- | -------------------- |
| 행복 | `assets/happy.png`   |
| 평온 | `assets/calm.png`    |
| 보통 | `assets/neutral.png` |
| 우울 | `assets/sad.png`     |
| 화남 | `assets/angry.png`   |

Figma에서 다운로드한 파일은 `assets/figma`에 별도로 저장했습니다.

- `warm-evening.png`: A-01의 그림 레이어 241:1863. 시작과 샘플 일기 카드/상세에서 3:2로 표시.
- `back`, `close`, `chevron-right`, `settings`, `share`, `refresh`, `send`, `pencil`, `google` PNG:
  Figma 00의 아이콘 레이어를 내보냈습니다. 기본 24px, Google 버튼에서는 20px.
- Lucide는 새 본문 이동 버튼과 공통 체크박스에 사용합니다.
- Noto Sans KR 400/500/700은 `@expo-google-fonts/noto-sans-kr`의 로컬 폰트 파일을
  `expo-font`로 로딩합니다. 글꼴을 받기 위한 런타임 네트워크 요청은 없습니다.
- 만료되는 Figma 에셋 URL은 실행 코드에서 사용하지 않습니다.

## Mock 동작과 재현

Google 로그인은 약 650ms, 저장은 1초, 그림 생성은 6초, 검색은 700ms 후 완료됩니다.
기록의 그림은 Figma의 고정 예제 그림을 재사용합니다. 실제 AI 생성은 하지 않습니다.
검색은 감정 동의어, 활동 태그, 월 조건과 원문을 이용한 로컬 검색입니다.
답변의 기록 개수는 실제 검색된 Mock 데이터로 계산합니다.

작성 초안은 뒤로 가기 후에도 유지됩니다. 중복 저장을 차단하며, 저장 실패 시 초안을 지우지 않습니다.
그림 생성 작업은 화면 생명주기와 분리되어 홈에서 기다려도 완료됩니다.
생성 실패 시 저장된 기록은 유지하고 그림만 재시도합니다.
상태는 메모리에만 유지됩니다. 로그아웃 후 같은 실행 세션에서 다시 로그인하면 기록을 볼 수 있지만,
앱 전체 재시작/웹 새로고침 시 예제 상태로 초기화됩니다.

개발 중 설정의 **개발용 화면 미리보기**, 홈 제목 길게 누르기 또는 `/dev` 딥 링크로
00~04 카탈로그를 엽니다. 이 화면에서 성공/실패/로딩 상태를 재현할 수 있습니다.
오류 주입은 다음 요청 한 번에만 적용되므로 재시도는 성공합니다.

- 저장 실패: **E-02 저장 실패** → **기록 저장하기** → 오류와 초안 확인 → **다시 저장하기**.
- 그림 실패: **E-03 생성 실패 경로** → 저장 → 생성 실패 → **다시 그리기**.
- 검색 실패: **E-05 검색 · 실패** → **다시 물어보기**.
- 빈 검색: **눈 오는 날 기록 보여 줘** 입력.
- 로그인 실패: **E-06 Google 로그인 실패** → **Google로 시작하기** → 배너 → 재시도.
- 캘린더 빈 날짜: 2026년 10월 18일 선택.
- 로그아웃: 설정 → 로그아웃 → 취소/확인.

`/dev`는 `__DEV__` 보호 라우트이며 프로덕션에서 열리지 않습니다.

## 검증 명령

```sh
npm run typecheck
npm run lint
npm run format:check
npm test -- --runInBand
npx expo install --check
npm run doctor
npx expo export --platform android --platform ios --max-workers 2 --output-dir dist/native
```

자동 검증은 타입·린트, 로그인부터 캘린더 상세까지의 라우팅, 중복 저장 방지,
오류 후 입력 보존/재시도, 화면 이탈 후 그림 완성, 검색 결과/오류/빈 상태,
로그아웃 후 보호 라우트 접근 차단, 날짜 경계/윤년을 포함합니다.

MCP 디자인 컨텍스트·스크린샷과 소스의 토큰/간격/이미지 슬롯을 대조했습니다.
브라우저 제어 도구에 연결된 브라우저가 없어 렌더된 화면 스크린샷 비교와 실기기 터치·키보드·
Safe Area 시각 검증은 이 환경에서 수행하지 못했습니다. 배포 전 390×844와 작은 기기에서
입력창 키보드, 시트, Android 뒤로 가기 및 iOS 제스처를 확인해야 합니다.

## 미연동 범위

실제 Google OAuth, 백엔드, AI 이미지 생성, 결제, 푸시 알림, 그림 앨범 저장/공유,

준비 중 안내를 표시합니다. 05 이후 및 하단 탭은 구현 범위에서 제외했습니다.
