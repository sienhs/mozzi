# 비교 실험 설계 — 조합을 나눈 이유와 전체 목록

모찌 LoRA 실험이 **무엇을 비교하는지**, 그리고 **조합을 왜 이렇게 나눴는지** 정리한 문서다.

- 실행 목록의 원본: [configs/experiment_matrix.yaml](configs/experiment_matrix.yaml) (`run_matrix.py`가 이 파일을 읽는다)
- 측정 규약과 기록 형식: [README.md](README.md) 6장
- 실행 기록: [experiments.md](experiments.md), 결과 표: `results/*.csv`, `results/report/`

---

## 1. 이 실험이 답하려는 질문

| # | 질문 | 왜 중요한가 |
|---|---|---|
| Q1 | **LoRA를 학습한 효과가 있나?** | 학습 없이 프롬프트나 참조 이미지만으로 충분하다면, 학습 비용을 들일 이유가 없다 |
| Q2 | **6GB 노트북에서는 어떤 정밀도로 돌려야 하나?** | 원본(bf16)은 6GB에 들어가지 않는다. 양자화로 속도, 메모리, 화질이 각각 얼마나 바뀌는지 알아야 한다 |
| Q3 | **학습은 몇 step이 적당한가?** | 너무 짧으면 캐릭터를 못 배우고, 너무 길면 캡션을 무시한다(과적합) |
| Q4 | **6GB에서 어떤 설정으로 학습할 수 있나?** | 학습 정밀도와 rank에 따라 OOM, 속도, 품질이 달라진다 |

## 2. 왜 조합을 나눴나

**한 번에 하나만 바꾸고 나머지는 고정한다.** 두 가지를 동시에 바꾸면, 결과가 좋아져도 무엇 덕분인지 알 수 없다.

- Q1(LoRA 효과)을 볼 때는 precision을 **fp8로 고정**하고 *방법*만 바꾼다.
- Q2(양자화)를 볼 때는 방법을 **klein_lora로 고정**하고 *precision*만 바꾼다.
- Q3(step)를 볼 때는 같은 학습 run의 체크포인트를 *step*만 바꿔 같은 조건으로 돌린다.

### 모든 추론 조합에 공통으로 고정한 조건

| 항목 | 값 |
|---|---|
| 프롬프트 | `dataset/prompts/test.csv` 40개 (스윕은 `val.csv` 12개) |
| seed | `seeds.txt` 앞에서부터, 프롬프트당 1개 |
| 생성 | FLUX.2 klein **distilled** 4B, 4-step, guidance 1.0 |
| 해상도 | 768 (1차) / 1024 (2차) |
| 텍스트 인코더 | Qwen3-4B, 항상 bf16 (precision은 트랜스포머에만 적용) |
| 환경 | RTX 4050 Laptop 6GB, 전원 연결 |

### 우선순위를 나눈 이유

노트북 한 대로 돌리기 때문에 시간이 한정돼 있다. 그래서 Q1과 Q2에 바로 답하는 768 조합을 **1차**로 먼저 돌린다. 1024 해상도와 나머지 precision은 2·3차로 미룬다.

| 우선순위 | 의미 |
|---|---|
| 1 | 먼저 돌릴 것. 발표에 꼭 필요한 비교 |
| 2 | 1차 결과를 보고 시간이 되면 |
| 3 | 시간이 남으면 (표를 채우는 용도) |

## 3. 추론 비교 (Q1, Q2)

### 3-1. 방법(method): 모찌를 모델에 어떻게 알려 주나

| method | 입력 | 학습 필요 | 역할 |
|---|---|---|---|
| `klein_base` | 긴 생성 프롬프트 (생김새·화풍을 글로 설명) | ✗ | **하한선.** 글만으로 어디까지 되나 |
| `klein_ref` | 긴 프롬프트 + anchor 이미지(`outputs/anchors/{mood}.png`) | ✗ | 학습 없이 참조 이미지로 되나 |
| `klein_lora` | 짧은 캡션(`mochi_char, …`) + 화풍 문구(`inference_style`) | ✓ | **학습 효과** (서비스 후보) |
| `api_ref` | 긴 프롬프트 + anchor, 외부 이미지 API | ✗ | 유료 외부 모델과 비교 (공급자 미정) |

LoRA가 없는 방법은 `mochi_char`라는 단어를 모르기 때문에 긴 프롬프트를 쓴다. 대신 같은 앱 입력에서 만든 프롬프트이므로 조건은 공정하다.

### 3-2. 정밀도(precision): 트랜스포머를 얼마나 줄이나

| precision | 방식 | 트랜스포머 크기 |
|---|---|---|
| `bf16` | 원본 | 7.75GB (6GB 초과) |
| `fp8` | 원본을 실행할 때 fp8로 저장 (layerwise casting) | 약 3.9GB |
| `gguf_q8` | 미리 양자화된 8bit 파일 (unsloth) | 약 4.3GB |
| `gguf_q4` | 미리 양자화된 4bit 파일 (Q4_K_M) | 약 2.6GB |

### 3-3. 1차 (768px) — `run_matrix.py --kind inference --priority 1`

| 조합 | method | precision | 답하는 질문 | 비고 |
|---|---|---|---|---|
| `base_fp8_768` | klein_base | fp8 | Q1 | 하한선 |
| `ref_fp8_768` | klein_ref | fp8 | Q1 | |
| `lora_fp8_768` | klein_lora | fp8 | **Q1 + Q2** | 두 비교에 모두 들어가는 기준 조합 |
| `lora_bf16_768` | klein_lora | bf16 | Q2 | 6GB 초과. 장당 120초를 넘으면 `too_slow`로 기록 (실패도 결과) |
| `lora_gguf_q8_768` | klein_lora | gguf_q8 | Q2 | |
| `lora_gguf_q4_768` | klein_lora | gguf_q4 | Q2 | |
| `api_ref_768` | api_ref | – | Q1 | 이미지 API 공급자가 정해진 뒤 실행 가능 |

```
            Q1: LoRA 효과 (fp8 고정)
            base ── ref ── lora ── api
                           │
            Q2: 양자화      │ (klein_lora 고정)
            bf16 ── fp8 ── q8 ── q4
```

### 3-4. 2차 (1024px) — 1차와 같은 7개 조합을 1024로

`base_fp8_1024`, `ref_fp8_1024`, `lora_fp8_1024`, `lora_bf16_1024`, `lora_gguf_q8_1024`, `lora_gguf_q4_1024`, `api_ref_1024`

→ 해상도를 올렸을 때 화질이 좋아지는 만큼 속도와 메모리가 얼마나 나빠지는지 본다.

### 3-5. 3차 — LoRA 없는 방법의 나머지 precision

`base_{bf16,gguf_q8,gguf_q4}_{768,1024}`, `ref_{bf16,gguf_q8,gguf_q4}_{768,1024}` (12개)

→ 표의 빈칸을 채우는 용도다. 결론에는 거의 영향이 없다.

## 5. 학습 비교 (Q4)

| 조합 | 학습 precision | rank | step | 우선순위 | 비고 |
|---|---|---|---|---|---|
| `train_smoke` | qfloat8 | 8 | 50 | 1 | 동작 확인 + s/it |
| `train_q8_r16` | qfloat8 | 16 | 2000 | 1 | **본 학습** |
| `train_bf16_r16` | bf16 | 16 | 60 | 1 | 6GB에서 OOM/too_slow인지 기록 |
| `train_q8_r8` | qfloat8 | 8 | 2000 | 2 | rank 비교 |
| `train_f8ao_r16` | float8 (torchao) | 16 | 60 | 3 | quanto qfloat8과 비교 |
| `train_uint4_r16` | uint4 | 16 | 60 | 3 | 4bit 학습이 되는지 |

학습 정밀도(qfloat8 등)는 **베이스 모델을 얼려 두는 형식**이다. 학습되는 LoRA는 항상 bf16이고, 추론 precision(3-2)과는 별개다.

## 6. 평가 지표

| 지표 | 비교 대상 | 의미 |
|---|---|---|
| `dino_sim_crop` | 주인공 모찌를 잘라낸 부분 ↔ 같은 기분의 anchor | **캐릭터 일관성 (주 지표).** OWLv2로 흰 모찌를 찾아 가장 큰 박스를 자른다 |
| `clip_i` | 이미지 전체 ↔ anchor (CLIP) | 전체적인 유사도 |
| `clip_t` | 이미지 ↔ 캡션 문장 | 프롬프트 충실도 |
| `dino_sim` | 이미지 전체 ↔ anchor (DINOv2) | 배경 영향이 커서 장면 이미지에서는 낮게 나온다 (참고용) |
| `latency_median_sec` | – | 장당 생성 시간 (4-step + VAE 디코드, 첫 장 제외) |
| `vram_peak_gb_torch`, `shared_peak_gb`, `sysmem_fallback` | – | 메모리 사용량. 6GB를 넘어 공유 메모리를 썼는지 |
| `human_score` | – | 팀원이 매기는 1~5점 (빈칸) |

숫자로는 화풍과 금지 규칙(사람, 글자, 동물)을 판단할 수 없다. 그래서 `results/report/`의 이미지 그리드를 **같이 본다**.

## 7. 지금까지 결과 (실측)

### 7-1. 학습

- **10/22 768 스모크 테스트:** 7.08 s/it, 6GB 안에서 돌아감
- **10/22 1024 스모크 테스트:** 12.35 s/it, 공유 메모리 사용 → **768로 결정**
- **10/23 본 학습 `20261023_train_qfloat8_r16`:** 768, rank 16, 2000 step, 이미지 56장
  - 안정 구간 6.0~6.2 s/it, 학습 합계 약 204.6분
  - step 1500 샘플링 직후 느려져서 중단하고 재개함 (`TODO.md` 10/23 참고)

### 7-2. 체크포인트 스윕 (fp8/768, val 12, 화풍 문구 없이)

| step | 250 | 500 | 750 | 1000 | 1250 | 1500 | 1750 | 2000 |
|---|---|---|---|---|---|---|---|---|
| dino_crop | 0.379 | 0.398 | 0.445 | 0.455 | 0.454 | 0.459 | **0.483** | 0.460 |
| clip_t | 34.11 | 34.81 | 33.83 | 33.43 | 34.59 | 34.55 | 34.39 | 34.31 |

- 캐릭터는 750 step 무렵 거의 다 배웠다. 과적합 신호(clip_t 하락)는 없다.

### 7-3. 추론 프롬프트 시험 (s2000, val 12)

| 버전 | dino_crop | clip_i | clip_t |
|---|---|---|---|
| 캡션만 | 0.460 | 0.745 | 34.31 |
| + 화풍 문구 | 0.551 | 0.752 | 33.72 |
| + 화풍 문구 + coworker 표현 변경 | 0.559 | 0.761 | 34.19 |

- 화풍 문구로 close-up 장면이 실사풍으로 나오던 문제가 해결됐다. 이후 `klein_lora`의 기본값으로 정했다.
- coworker 표현에서 직업 단어를 빼자, 사람으로 그려지던 문제가 해결됐다.

### 7-4. 양자화 속도 (10/20, 스모크 LoRA, 768, 화질은 측정하지 않음)

| precision | 장당 시간 | VRAM torch | 공유 메모리 사용 |
|---|---|---|---|
| fp8 | 9.38s | 5.21GB | 있음 |
| gguf_q4 | 8.51s | 3.99GB | 없음 |
| bf16 (base) | – | – | too_slow (warmup 1장이 5분 넘게 걸림) |

→ 1차 매트릭스(3-3)에서 **본 LoRA로 화질까지** 다시 잰다 (7-5).

### 7-5. 1차 비교 실험 (10/23, test 40, 768, LoRA s2000 + 화풍 문구)

| 실행 | 장당 (중앙값) | VRAM torch | 공유 메모리 | dino_crop | clip_i | clip_t |
|---|---|---|---|---|---|---|
| klein_base fp8 | 7.52s | 5.19GB | 넘침 | 0.560 | 0.699 | 33.80 |
| klein_ref fp8 | 69.35s | 5.35GB | 넘침 | 0.580 | 0.734 | 34.05 |
| klein_lora fp8 | 8.15s | 5.23GB | 넘침 | 0.552 | 0.743 | 34.27 |
| klein_lora gguf_q8 | 9.49s | 5.60GB | 넘침 | 0.544 | 0.746 | 34.28 |
| **klein_lora gguf_q4** | **7.49s** | **4.01GB** | **없음** | 0.548 | 0.742 | 34.45 |
| klein_lora bf16 | too_slow (장당 상한 120초 초과) | | | | | |
| api_ref | 실행 못 함 (API 공급자 미정) | | | | | |

- **Q2 (양자화):** 화질 지표 차이는 작고, q4가 가장 빠르며 6GB 안에 들어가는 유일한 정밀도다 → 서비스 후보는 **gguf_q4**.
- **Q1 (LoRA 효과):** dino_crop은 base·ref가 약간 높고 clip_i는 LoRA가 높다. 입력 프롬프트가 달라서(짧은 캡션 vs 긴 설명) 지표만으로는 결론을 내리지 않는다. 그리드와 사람 평가로 확인한다.
- 리포트: `results/report/20261023/`

### 7-6. 특색(뽑기) 캐릭터 재현 (10/26, gguf_q4, 768, val 5장)

레몬·수박·우비 캐릭터로 시험했다 (`scripts/variant_test.py`). 장당 시간: LoRA + 글 7.5초, LoRA + 글 + 참조 1장 12.9초.
- **LoRA + 글 + 참조(B)가 가장 정확하다.** 참조가 1장뿐이어도 된다. 표정은 장면을 따르고 참조에서는 옷과 소품만 가져온다.
- 참조만 쓰거나(C), 글 없이 LoRA + 참조만 쓰면(D) 소품이 동행에게 옮겨 가거나 빠진다.
- 들고 있는 소품(`holding ...`, 우산)은 일기 장면의 소품을 밀어내고 실내에도 나온다. 입는 것과 드는 것을 나눠야 한다.
- 상세: `experiments.md` 10/26 항목

## 8. 주의할 점 (보고할 때 명시)

- **test 세트 수:** 원래 사양 문서에는 34개로 되어 있지만, 실제 구성은 24+6+6+4 = **40개**다.
- **화풍 문구 적용 범위:** 체크포인트 스윕(7-2)은 화풍 문구 **없이** 돌렸다. 1차 매트릭스부터는 `klein_lora`에 화풍 문구가 기본으로 붙는다.
- **학습 캡션과 추론 문구의 차이:** 본 LoRA(v1)는 예전 coworker 표현으로 학습했다. 추론에서는 새 표현을 쓴다.
- **api_ref:** 이미지 API 공급자(`{{IMAGE_API_PROVIDER}}`)가 정해지기 전까지는 실패로 기록된다.
- **표본 크기:** val은 12장, seed 1개다. 0.02 정도의 점수 차이는 우연일 수 있다.
